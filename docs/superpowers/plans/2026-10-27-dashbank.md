# DashBank Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Local finance tracker for Hapoalim + Isracard/Cal/Max with dashboard and Telegram/ntfy push on every new charge.

**Architecture:** Single Node.js process. node-cron triggers `runSync` → israeli-bank-scrapers → normalize/dedupe → SQLite → categorize → recurring detection → notifiers. Express serves a static RTL dashboard + JSON API on 127.0.0.1.

**Tech Stack:** Node >= 22.13 (ESM, `node:sqlite`, `node:test`, global `fetch`), express@5, node-cron@4, chart.js@4 (served from node_modules), israeli-bank-scrapers@6.12.2, dotenv.

## Global Constraints
- ESM (`"type": "module"`), no TypeScript, no new runtime deps without approval.
- Tests: `node:test` + `node:assert/strict`, files `tests/*.test.js`, run with `npm test`. No network in tests (inject `fetch`/scraper fakes).
- Never log or return credentials/passphrases. Server binds `127.0.0.1`.
- Amount sign: negative = money out, positive = money in. Currency default `ILS`.
- Hebrew user-facing strings; code/comments in English.
- Logging via `import { log } from './log.js'` (`log.info(msg, meta)`).
- DO NOT `git commit` — the coordinator commits after review.

### Task A: Categorization + recurring detection
**Files:** Create `src/categorize.js`, `src/recurring.js`, `tests/categorize.test.js`, `tests/recurring.test.js`
**Produces:**
- `categorize(description, { source, amount } = {}) → string`
  - If `BANK_SOURCES.has(source)` and description matches a card company (ישראכרט, כאל, ויזה כאל, מקס, לאומי קארד, אמריקן אקספרס, דיינרס, ישראכרט בע"מ, "max it") → `CARD_SETTLEMENT_CATEGORY`.
  - `amount > 0` and matches salary terms (משכורת, שכר, salary) → `'משכורת'`; other positive → `'הכנסה'` unless a rule matches (e.g. ביטוח לאומי → `'קצבאות'`, העברה → `'העברות'`).
  - Keyword rules (case-insensitive, Hebrew + English) for: `'מזון וסופר'` (שופרסל, רמי לוי, יוחננוף, ויקטורי, טיב טעם, מגה, אושר עד, AM:PM, יינות ביתן), `'מסעדות וקפה'` (ארומה, קפה, מסעדה, וולט, wolt, תן ביס, 10bis, מקדונלד, דומינו), `'תחבורה ודלק'` (פז, דלק, סונול, דור אלון, ten, רב קו, רכבת, gett, yango, מוניות, חניה, פנגו, סלופארק, כביש 6), `'תקשורת'` (סלקום, פרטנר, פלאפון, הוט, בזק, גולן, 012, 019, yes), `'מנויים ודיגיטל'` (netflix, spotify, apple, google, youtube, disney, chatgpt, openai, anthropic, claude, amazon prime, microsoft, adobe, דיסני), `'חשבונות בית'` (חברת החשמל, חשמל, מי , תאגיד, ארנונה, עירייה, גז, סופרגז, אמישראגז, ועד בית), `'ביטוח ובריאות'` (ביטוח, הראל, מגדל, כלל, הפניקס, מנורה, מכבי, כללית, מאוחדת, לאומית, סופר-פארם, בית מרקחת), `'קניות'` (amazon, aliexpress, ali express, shein, איקאה, ikea, זארה, h&m, kSP, באג, ivory), `'חינוך'` (אוניברסיטה, בר-אילן, בר אילן, שכר לימוד, קורס, udemy, coursera), `'פנאי'` (סינמה, יס פלאנט, cinema, הופעה, כושר, holmes, גו אקטיב), `'משיכת מזומן'` (משיכה, כספומט, atm), `'עמלות'` (עמלה, דמי ניהול, ריבית), `'הוראות קבע'` (הוראת קבע, הו"ק).
  - Fallback `'אחר'`.
  - Export `CATEGORIES` (array of all names) and `RULES` (array of `{category, patterns: string[]}`) for reuse.
- `detectRecurring(txns, { now = new Date() } = {}) → Recurring[]`
  - Group by `key = source + '|' + normalized description` (lowercase, strip digits, punctuation and extra spaces; ignore installment txns where `installmentTotal > 1`).
  - Only outgoing (`amount < 0`) and incoming salaries (`amount > 0`, kind `'income'`) groups with ≥ 3 occurrences in distinct calendar months.
  - Amount tolerance: every amount within ±15% of the median.
  - Median day gap between consecutive txns in [25, 35] → cadence `'monthly'`; in [6, 8] → `'weekly'`; in [355, 375] → `'yearly'` (needs only 2 occurrences). Otherwise skip.
  - `kind`: description contains הוראת קבע/הו"ק or bank source → `'standing_order'`; matches subscription keywords from the categorize rules for `'מנויים ודיגיטל'` → `'subscription'`; positive → `'income'`; else `'recurring'`.
  - Output: `{ key, description (latest original), source, avgAmount (mean, 2dp, signed), cadence, count, lastDate (ISO day), nextDate (lastDate + 1 month/7 days/1 year, ISO day), kind, active }` where `active = (now - lastDate) <= 1.5 × cadence period`.
  - Sorted by `avgAmount` ascending (largest outflow first).
**Tests (must include):** card-settlement only for bank sources; salary; 5+ representative merchants; fallback; monthly Netflix ×4 detected as subscription with correct nextDate; weekly; amounts outside ±15% rejected; only 2 monthly occurrences rejected; installments ignored; inactive flagged.

### Task B: Vault + notifiers + setup CLI
**Files:** Create `src/vault.js`, `src/notify/format.js`, `src/notify/telegram.js`, `src/notify/ntfy.js`, `src/notify/index.js`, `scripts/setup.js`, `scripts/test-notify.js`, `tests/vault.test.js`, `tests/notify.test.js`
**Produces:**
- `vault.js`: `encryptVault(obj, passphrase) → Buffer` (format: magic `DBV1` 4 bytes | salt 16 | iv 12 | tag 16 | ciphertext; key = `scrypt(passphrase, salt, 32, {N: 2**15, r: 8, p: 1, maxmem: 64*1024*1024})`, AES-256-GCM), `decryptVault(buf, passphrase) → obj` (throws `Error('סיסמת כספת שגויה או קובץ פגום')` on auth failure), `readVault(file, pass)`, `writeVault(file, obj, pass)` (atomic write tmp+rename, mode 0o600). Vault object shape: `{ accounts: [{ id, companyId, label, credentials: {...} }] }`.
- `notify/format.js`: `formatTxn(txn) → { title, body, tags, priority }`. Outgoing: title `💳 ₪123.45 · <description>`, body lines: source label (`SOURCE_LABELS`) + `•` last 4 of accountNumber, category, date `DD/MM HH:mm` Asia/Jerusalem, installments `תשלום 2/12`, foreign currency `($40.00)`, pending `⏳ ממתין לאישור`. Incoming: `💰 +₪12,000.00 · <description>`. ILS formatting via `Intl.NumberFormat('he-IL', {style:'currency', currency:'ILS'})`. `priority`: 4 if |amount| ≥ 1000, else 3. `formatSummary(newTxns) → text` (count, total out/in, top 5 by size).
- `notify/telegram.js`: `createTelegram({ token, chatId }, { fetch }) → { name:'telegram', send({title, body}) }` → POST `https://api.telegram.org/bot<token>/sendMessage` JSON `{ chat_id, text: '<b>'+escapeHtml(title)+'</b>\n'+escapeHtml(body), parse_mode: 'HTML', disable_web_page_preview: true }`. Throw on non-2xx with status (never include token in message).
- `notify/ntfy.js`: `createNtfy({ server, topic, token }, { fetch }) → { name:'ntfy', send({title, body, tags, priority}) }` → POST to `server` root URL (ntfy JSON publish; strip trailing `/`) with `Content-Type: application/json` body `{ topic, title, message: body, tags, priority }` — JSON avoids non-ASCII header problems with Hebrew titles, header `Authorization: Bearer <token>` when token set.
- `notify/index.js`: `createNotifier(config, { fetch = globalThis.fetch } = {}) → { channels: string[], notifyTxn(txn), notifySummary(newTxns, label), notifyError(label, message), sendRaw(title, body) }`. Enables channel only if configured. `notifyTxn` skips outgoing charges with `|amount| < config.notifyMinAmount`. Each channel send wrapped in try/catch → `log.warn`; never throws. `notifyError` dedupes by `label+message` per calendar day (in-memory). Returns `Promise<{sent, failed}>`.
- `scripts/setup.js`: interactive (`node:readline/promises`) CLI in Hebrew: load `.env` (`import 'dotenv/config'`), ask passphrase (or use `DASHBANK_PASSPHRASE`), load existing vault if present, menu: add account (choose from hapoalim/isracard/visaCal/max/amex/leumi/discount/mizrahi; prompt for that company's `SCRAPERS[companyId].loginFields` from `israeli-bank-scrapers`; password fields hidden via muted output), list accounts (no secrets), remove account, save & exit. Uses `loadConfig().vaultPath`.
- `scripts/test-notify.js`: loads config, `createNotifier`, sends a sample outgoing txn, prints which channels succeeded.
**Tests:** vault round-trip, wrong passphrase throws Hebrew error, tampered byte throws, magic check; formatTxn outgoing/incoming/installments/foreign/pending; telegram request URL/body via fake fetch; ntfy body + auth header; notifier skips unconfigured channels, min-amount filter, failing channel doesn't throw, error dedupe.

### Task E: Authentication — password + TOTP MFA, optional Google sign-in
**Files:** Create `src/auth/password.js`, `src/auth/totp.js`, `src/auth/session.js`, `src/auth/google.js`, `src/auth/routes.js`, `src/auth/store.js`, `public/login.html`, `public/login.js`, `scripts/auth-setup.js`, `tests/auth.test.js`; Modify `src/server.js` (mount auth, protect `/api/*` and app shell), `src/config.js`, `.env.example`, `package.json` (script `auth-setup`).
**Requirements:**
- No new deps. Use `node:crypto` only.
- `password.js`: `hashPassword(pw) → 'scrypt$N$r$p$saltB64$hashB64'` (N=2**15,r=8,p=1, 32-byte key), `verifyPassword(pw, stored)` with `crypto.timingSafeEqual`. Min length 10.
- `totp.js` (RFC 6238/4226): `generateSecret() → base32 (20 bytes)`, `totp(secret, {time, step:30, digits:6})`, `verifyTotp(secret, code, {window:1, time})` constant-time, `otpauthUrl({secret, account, issuer:'DashBank'})`. Tests against RFC 6238 SHA-1 vectors (secret ASCII "12345678901234567890": T=59 → 94287082 for 8 digits; T=1111111109 → 07081804; T=1234567890 → 89005924).
- `store.js`: auth config in `data/auth.json` (mode 0600): `{ users: [{ username, passwordHash, totpSecret (encrypted with AES-256-GCM using key derived from AUTH_SECRET), recoveryCodes: [hashes] }] }`. Single user is enough; schema supports list.
- `session.js`: stateless signed cookie `db_sess` = base64url(payload).HMAC-SHA256(AUTH_SECRET); payload `{u, exp, mfa:true}`; 12h expiry, sliding refresh; cookie flags `HttpOnly; SameSite=Strict; Path=/; Secure` when request is HTTPS (`req.secure` with trust proxy loopback) — allow non-secure on plain `http://127.0.0.1`. CSRF: SameSite=Strict + require header `X-Requested-With: dashbank` on non-GET `/api/*`.
- Login flow: `POST /auth/login {username,password}` → if OK returns `{ next: 'totp' }` and sets short-lived (5 min) `db_pre` cookie; `POST /auth/totp {code}` (or recovery code, single-use) → sets `db_sess`. `POST /auth/logout`. `GET /auth/me` → `{ user, methods }`. Rate-limit: in-memory, 5 failed attempts per IP+username per 15 min → 429. Generic error messages (no user enumeration).
- Google OIDC (enabled only if `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_ALLOWED_EMAILS` set): `GET /auth/google` → redirect to `https://accounts.google.com/o/oauth2/v2/auth` with `response_type=code, scope=openid email profile, state, nonce, code_challenge (S256), redirect_uri = PUBLIC_URL + '/auth/google/callback'`; callback exchanges code at `https://oauth2.googleapis.com/token`, then validates the `id_token` by verifying its RS256 signature against `https://www.googleapis.com/oauth2/v3/certs` (JWKS → `crypto.createPublicKey({key: jwk, format:'jwk'})`, cache 1h), checks `iss` ∈ {`https://accounts.google.com`, `accounts.google.com`}, `aud` = client id, `exp`, `nonce`, `email_verified === true`, and email ∈ allow-list. Google login counts as MFA-satisfied (Google account's own 2-step) — document this. `fetch` injectable for tests.
- `scripts/auth-setup.js`: interactive: create/replace user, password (hidden, confirm), generate TOTP secret, print otpauth URL **and render a QR code in the terminal**: no deps available, so instead print the otpauth URL + base32 secret for manual entry in Google Authenticator / Microsoft Authenticator / Aegis, and also write `data/totp-qr.html` that renders the QR client-side? — NO external libs: print secret + URL only, and ask user to enter a current code to confirm before saving. Generate 8 recovery codes, print once, store hashes.
- Server: if no `data/auth.json` exists and not demo → all routes redirect to `/login.html` which shows "run `npm run auth-setup`". Demo mode: auth disabled, banner says so. Static assets needed by login page (css, login.js, icons, manifest, sw.js) are public; `/`, `/app.js`, `/api/*` require session (API → 401 JSON; pages → 302 `/login.html`).
- `login.html`: same design system as dashboard (reuse styles.css), animated card, username/password step → 6-digit code step with auto-advance one-time-code input (`autocomplete="one-time-code"`, `inputmode="numeric"`), "המשך עם Google" button shown only when enabled (from `GET /auth/me` → methods), RTL, accessible labels, errors in `role="alert"`.
- Frontend `app.js`: send `X-Requested-With: dashbank` on POSTs; on 401 → redirect to login; add logout button.
**Tests:** RFC vectors; verify window ±1; password hash/verify/wrong; session sign/verify/tamper/expiry; login → totp → session → /api/overview 200; without session 401; wrong code ×5 → 429; recovery code works once; CSRF header required; Google callback with fake fetch + locally generated RSA key/JWKS: valid token accepted, wrong aud/nonce/unlisted email/unverified rejected.
